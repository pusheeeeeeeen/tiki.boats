Deep equals

with infinite recursion

Usage

Download the minified or unminified source code. There is no CDN. Just download it.

Call deepEquals(a, b) with any two values (a and b) to check if they are deeply equal. Values are considered equal if the === operator returns true, or all keys and values match. See comparison rules for more info.

Examples

The deepEquals function can be used for non-recursive data structures and recursive ones. These examples show a variety of use cases and their expected outputs.

Basic deep equality comparison

returns true (object keys are unordered): 
deepEquals(
  {a: 1, b: ["some", "strings"]},
  {b: ["some", "strings"], a: 1}
)
returns false (array order matters): 
deepEquals(
  {a: 1, b: ["some", "strings"]},
  {a: 1, b: ["strings", "some"]}
)

Custom comparison function

returns true (custom comparison function uses loose equality operator): 
deepEquals(
  [123, null, null],
  ["123", null, undefined],
  (a, b) => a == b
)

Infinite recursion

returns true (both objects allow obj.a.b.a.b.a.b... forever): 
let obj1 = {}, obj2 = {}

obj1.a = {b: obj1}
obj2.a = {b: {a: {b: obj2}}}

deepEquals(obj1, obj2)
returns false (objects start out the same, but obj2 has two b’s in a row: obj2.a.b.a.b.b): 
let obj1 = {}, obj2 = {}

obj1.a = {b: obj1}
obj2.a = {b: {a: {b: {b: obj2}}}}

deepEquals(obj1, obj2)

Prototype chain checking

returns false (objects do not have the same prototype chain): 
deepEquals(
  {},                 // <empty object> -> Object.prototype -> null
  Object.create(null) // <empty object> -> null
)
returns true (prototype chains are identical): 
// <empty object> -> {a: 5} -> Object.prototype -> null
deepEquals(
  Object.create({a: 5}),
  {__proto__: {a: 5}}
)

Comparison Rules

There are a few steps that are gone through to determine if two values should be considered equal. They are executed in this order:

  1. If the values are equal using the strict equality operator (===), then return true.
  2. Otherwise, check which values are primitives. If one is and the other isn’t, return false. Keep in mind that two different symbols with the same name will not be considered equal, as that is how the JavaScript strict equality operator treats symbols.
  3. If both values are primitives: return the result of the custom comparison function if it is defined, otherwise false.
  4. Otherwise, if one value is a JavaScript set or map and the other isn’t, return false. (This also applies if one is a set and the other is a map).
  5. If both values are maps, then check that both maps have the same keys, and the keys correspond to the same values. Keys are compared using Map.prototype.has("key"), meaning that maps are only considered equal if the keys are strictly equal to each other.* Map values, however, are compared by recursively calling the deepEquals function.
  6. If both values are sets, then check that both sets contain the same values. Like map keys, set values are compared using Set.prototype.has(value), so they must be strictly equal.*
  7. If none of the above conditions are met, the values are treated as plain JavaScript objects. Both objects must have the same keys, and the keys must correspond to the same values. Values are compared by recursively calling deepEquals. The prototype of the object is also checked using deepEquals, so two objects that have the same properties but a different prototype chain will not be considered equal (unless the two prototype chains are deeply equal).

Other notes:

  • Property descriptors such as writable and enumerable are not checked when comparing objects.
  • The keys and values of weak maps and weak sets are not compared. This is because it is not possible to get a list of the keys of a weak map or the values in a weak set.
  • WeakRefs are not de-referenced when they are compared, so two WeakRefs that point to different values will still be considered equal.
  • There are many possible data structures that store data internally that is only accessible through calling methods, which will not be checked by the deepEquals function. Keep in mind that aside from the special handling of maps and sets, values are only checked for equality if they are accessible through Object.keys() or the prototype chain (Object.getPrototypeOf()).

Custom Comparison Functions

A callback can be provided as the third optional parameter to deepEquals. The callback takes two parameters—the values to check the equality of—and returns the result of the comparison (which is converted to a boolean). This function is only called if the two values are not strictly equal (===), and both values are primitives.

Note that because this function runs after the strict equality check, this function can’t override comparisons that would normally be considered strictly equal. So, this function can only make pairs of primitives that would normally be not equal considered equal, and not the other way around.

*Map keys and set values are compared using strict equality (via built-in functions) due to performance reasons. To compare map keys or set values using the deepEquals function, it would require checking every possible combination, which would be very slow, especially due to the slow nature of deep equality checking.
